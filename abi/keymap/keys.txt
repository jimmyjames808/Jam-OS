# The keys Jam OS knows, whatever the layout: each key's name, its HID
# usage and its Linux evdev key code. tools/genkeymap.py reads this file
# with a layout file (us.txt) and makes user/lib/keymap_keys.c (the HID
# usage to evdev code table) and, per layout, the C table and the XKB
# keymap (user/lib/keymap_<layout>.c). `make keymap` makes them again;
# `make check` fails if they are stale.
#
# One key a line:   <name> <usage> <evdev> [comment]
#   name    XKB's name for the key (as in its "evdev" key codes, written
#           without the < >): AE01 is the second key of row E, the digit
#           row; RTRN is Return. A layout file names keys by it, and the
#           XKB keymap's key numbers are the evdev code + 8.
#   usage   the USB HID usage, Keyboard/Keypad page (0x07), in hex (USB HID
#           Usage Tables 1.4, section 10): what hid reports.
#   evdev   the Linux key code Wayland sends for it (the numbers of Linux's
#           input-event-codes.h, used as facts; a decimal number).
# Two usages may give one key (0x31 and 0x32 are both BKSL, as Linux maps
# them); a usage is listed once. The usage-to-code pairs are Linux's own
# (its hid-input table), so a ported program sees the codes it would on
# Linux. Usages not listed have no code (0).
#
# The 105 keys of a PC keyboard, then the keypad's =, F13-F24, Power and
# the volume keys.
