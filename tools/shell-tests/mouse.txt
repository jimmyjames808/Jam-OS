# The mouse, end to end: run by tools/mouse-test.sh (QEMU_USB = a usb-kbd
# on xhci port 2 and a usb-mouse on port 3; the command line "shell", at
# OVMF's 1280x800). QEMU's monitor moves the mouse and presses its buttons
# (`mouse_move dx dy [dz]`, `mouse_button <bits>`: 1 left, 2 right); the
# reports go usb-bus -> drv/hid -> console, and from there only to a
# focused client that asked for them.
#
# The pointer is put somewhere exact by pushing it into the top-left
# corner (it is clamped there) and moving on from (0, 0); mines runs with
# `noaccel`, so a count is a pixel. At 1280x800 the Intermediate board's
# cells are 38 pixels and its top-left corner is at (336, 96): cell (c, r)
# has its middle at (355 + 38 c, 115 + 38 r). With seed=5 and the first
# reveal on (8, 8), cell (7, 8) shows a 1 whose mine is at (6, 7).
wait 120 Jam OS shell
wait jam>
seen 30 boot mouse ready
# The shell never asked for the mouse: moving it, clicking and turning the
# wheel sends it nothing (its line editor would misread any message), and
# the wheel scrolls the console back as before.
send help
wait Commands:
wait jam>
monitor mouse_move 60 -40
monitor mouse_button 1
sleep 0.2
monitor mouse_button 2
sleep 0.2
monitor mouse_button 0
monitor mouse_move 0 0 1
monitor mouse_move 0 0 1
sleep 0.7
shot mouse-scrollback
send echo mouse-$HOME
wait mouse-/boot
wait jam>
