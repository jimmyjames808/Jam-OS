# More terminals (docs/G1-PLAN.md, track T1): on a plain boot init starts
# the compositor before the console, and each console
# runs in window mode (a window of the compositor's once it offers
# xdg_wm_base; without one, its text goes to COM1 only). `term` opens
# terminal 2, a console and a shell of their own (its output is copied to
# COM1 too, so its banner shows here). Its shell and its console killed
# are started again, as the first terminal's are; the compositor killed,
# both consoles connect again; the first terminal answers throughout.
# Then terminals up to the limit (16 in all, <deskapps.h> TERMINALS_MAX),
# each `term` typed once the last one's window is up and has the keys;
# terminals 10 to 16 by their two-digit names too (`kill console-12`,
# `kill shell-16`: started again). At 1280x800 a screen holds five tiles:
# the sixth terminal's split would leave a tile under the tiler's minimum
# (200 pixels wide), so it opens on a new screen, and so on (screens 1 to
# 3 with five each, the 16th alone on screen 4); Super+1 goes back to the
# first. `term` refuses one more, naming the limit; Super+Enter on the
# USB keyboard is refused too, and the desktop says so: the notice "No
# more terminals / 16 is the most. Close one first." (in the log as
# every notice), and only one while it is up (a second Super+Enter at
# once posts none). `free` before and after: the memory 15 more
# terminals take.
# Screenshots: terms-boot (the first terminal), terms-last (the 16th
# alone on the last screen), terms-first (the first screen, five tiles),
# terms-full (the notice).
# Typing into terminal 2 and closing it (`exit`, its close circle):
# terms-windows.txt and desktop.txt.
