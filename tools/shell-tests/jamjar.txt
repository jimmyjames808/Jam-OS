# jamjar, the music player's window (user/apps/jamjar): use
# tools/jamjar-test.sh (it makes the library on /data/music, adds the
# audio devices, a USB keyboard and mouse). At OVMF's 1280x800: the mouse
# targets below are that layout's (`noaccel`: a pixel a count).
#   1. the self-test; `run jamjar` has no player: it says so, shows the library
#   2. the shell's `jamjar`: play an album by keys, next, back, pause and
#      on, volume; search for the 1 kHz tone and play it: the bands' loudest
#      is band 8; help, the roulette, the full jar, the sleep timer
#   3. the mouse: the next button, a volume drag, a splash, a double-click
#   4. q: the music plays on

wait jam>

seen 60 music: ready
seen 30 report mouse ready

# ---- 3: the mouse ------------------------------------------------------------------------
# Each target is reached from the top-left corner (the pointer is clamped
# there), a pixel a count. QEMU's mouse sends at most 127 counts a report
# and merges moves not sent yet, so each move gets time to arrive before
# the next. The next button's middle is (1064,411).
monitor mouse_move -3000 -3000
sleep 1
monitor mouse_move 1064 411
sleep 0.6
monitor mouse_button 1
sleep 0.15
monitor mouse_button 0
wait 10 jamjar: click 1064,411
wait jamjar: next
# the volume slider (770..998 x 467..479): a drag from 900 to 840
monitor mouse_move -3000 -3000
sleep 1
monitor mouse_move 900 473
sleep 0.6
monitor mouse_button 1
sleep 0.15
monitor mouse_move -60 0
sleep 0.3
monitor mouse_button 0
wait 10 jamjar: click 900,473
# the jam (from y 632): a splash
monitor mouse_move -3000 -3000
sleep 1
monitor mouse_move 640 760
sleep 0.6
monitor mouse_button 1
sleep 0.1
monitor mouse_button 0
wait 10 jamjar: click 640,760
sleep 0.3
shot jamjar-splash
# a double-click on the first track row (tracks: x 462..696, row 0 y 114..139)
monitor mouse_move -3000 -3000

sleep 0.6

monitor mouse_button 0

monitor mouse_button 0
