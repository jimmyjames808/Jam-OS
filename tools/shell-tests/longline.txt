# Lines longer than the terminal is wide (user/services/shell/main.c: the
# line editor scrolls a long line sideways in its row, with a marker at a
# cut edge, and runs all of it, up to LINE_MAX = 240 characters, at any
# width). A plain boot with a USB keyboard and mouse at OVMF's 1280x800:
# terminal 1 (full width, cells 9x21 from (18, 58)) prints a 212-character
# line, whose two rows a triple click and a drag select and Super+C copies;
# `term` opens terminal 2 in the right half (about 67 columns), which takes
# the keys. There: a 208-character line typed and run whole; a 194-character
# line edited in its middle (96 lefts, "XYZ", a backspace: `longline-mid`);
# both recalled from the history (up, up) and run again; the copied text
# pasted (Ctrl+Shift+V, bracketed) and run whole; a long line typed, the gap
# between the tiles dragged 60 pixels left and back while it is on the line
# (`longline-resize-1`, `-2`: the line redrawn on its one row at each new
# width), then more typed and run whole. Each output waited for is built so
# it never appears in what was typed ("mark-"0123 types, mark-0123 shows;
# $T and $Q expand only when run).
# Run: QEMU_INPUT=tools/shell-tests/longline.txt \
#      QEMU_USB="-device usb-kbd,bus=xhci.0,port=2 -device usb-mouse,bus=xhci.0,port=3" \
#      tools/qemu-test.sh <dir> longline shell
