# M13.6 check: the ext filesystem (track R)

M13.6's independent review ([M13.6's plan](HISTORY.md#m136-the-ext-filesystem), since deleted: see git history; the R row):
everything M13.6 built, against its plan, read at main 4cb79cbe (U1 to U11b
and DB1 merged): the ext library (`user/services/extfs/ext/`, the journal
above all), the service (`user/services/extfs/`), `tools/jamext` and
extcheck's tests, `user/lib/fsview.c`, init's `tmp.c`, `jammounts.c` and
`mounts.c`, volumes' ext and drive-boot code, libc's U11b change in
`user/posix/sys/file.c`, and the grants (`user/lib/ns.c`) and approvals
(`user/lib/dataprog.c`) that DB1 and PO14 widened.

Looked at hardest, as the row asks: can a cut lose a synced file, or a
replay put old metadata over new data (U9's tail that moves after every
commit or two, nobody's reviewed); the parser against crafted volumes;
whether any path reaches outside the caller's namespace or a guarded
`etc` (DB1's one volume under two names, `/data` and `/jam`; the `/pkg`
view; the hidden-entry fix 02f80ab8); the restart cases.

Severity, as in the earlier checks: **High** loses or corrupts what was
answered, or is a hole a program can use; **Medium** is wrong behaviour the
system will meet; **Low** is a wart, a limit, or a hole only the shell or a
crafted system disk can reach.

Counts: **1 High, 2 Medium, 9 Low.** The High, both Mediums and two Lows
are fixed, one commit each with a test that failed before it; the other
seven Lows are reported (four of them the known limits the brief listed).

## Looked at and found sound

- **U9's tail move, at every point of a commit** (NVMe, FUA): a cut in the
  log's write leaves a torn transaction at the head that the scan stops
  at (the slot's id not committed: run again); after the commit block,
  the replay brings it home; during the home writes, the same; after them
  and before the journal superblock's write, the replay writes the same
  bytes home again; a torn superblock write can't happen in practice: every
  field a tail move changes (`s_start`, `s_sequence`, `s_checksum`) is in
  its first 512 bytes, and the second sector of its 1,024 never changes.
  The live set is cleared only when the tail reaches the head, so a block
  freed while any copy of it is replayable still gets its revoke; ids only
  grow, so an old lap's blocks never read as new.
- **A replay over new data**: data goes only to blocks the committed
  bitmaps call free or to a file's own; the one request that frees and
  then takes blocks (a write's) frees only blocks it took itself in the
  same transaction (`fwrite.c`, `extwrite.c`), so ext_alloc.h's rule "one
  request frees or writes new data, never both" holds.
- **The parser**: extcheck at ten times its counts (`--fuzz 30000 --storm
  30000`), twice with different seeds, clean under ASan and UBSan, and its
  cut storms at every block; extent nodes (depth, entries, order, bounds),
  inodes (`i_extra_isize`), directory blocks (`rec_len`), the journal
  superblock (`first`, `maxlen`, `start` against the inode) and every tag
  (inside the volume, outside the journal) are checked before use.
- **Paths**: `..` is the walk's own stack, never a directory's `..` entry,
  so it stops at the view's root whatever was renamed; an absolute link or
  `..` above the root is `ERR_LINK_OUT` and libc goes on in its own
  namespace (`path_again`), where its own views judge it; a subview's root
  is an inode and generation; a hard link from a guarded place and a name
  made, renamed or linked into one are refused where they resolve; readdir
  leaves out what the view hides where the listing lies.
- **DB1's one volume, two names**: a program's grant of `/jam` gets the
  same view flags as `/data`'s (`ns.c`: `NO_ETC`, and `GUARD_ETC |
  GUARD_PKG` if writable), so `/jam/etc`, which is `/data/etc` on a drive
  boot, is hidden and guarded alike; bin/pkg's `:wp` too. The installer
  refuses the boot disk; init's package settles of `/data` and `/jam`
  queue on one worker. The views of both names share the volume's table
  (R3).
- **`/tmp`'s pager and `/pkg`**: the pager's budget and rights are
  volumes'; the memory volume's job is init's; `/pkg` is a read-only
  subview, its grant `mount /pkg r` read-only and without `etc`;
  `dp_path_same` aliases only the package prefix, and the approval's hash
  still decides what runs.
- **U11b's `file.c`**: the description's lock, then the open's, on every
  path (`xfer`, `kind_seek`, `give_locked`); `given` is read and written
  under the description's lock; a description follows the children's end
  only if it was at the end when given (the documented per-process offsets
  otherwise).
- **02f80ab8's hidden entries**: every `fs` method's walk is judged where
  it resolves (`walk_found`, `op_resolve`, the open and the makers); what
  was left was R4's.
