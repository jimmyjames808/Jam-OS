# M9.5 review: network streams (focused)

An independent read of milestone M9.5 at main 6a8b36b..HEAD (local main, the
join + window scaling/bulk rings + the low-port permission + `update -w`
rename), by an agent that wrote none of it, against CODING-GUIDE.md,
SECURITY.md, ARCHITECTURE.md's networking section and docs/M9.5-PLAN.md. The
owner's choice was a **focused** review of the code that faces untrusted
input; drivers/rtl8125 and e1000e (M9's own track F), sntp/dns/dhcp/update
parsing (reviewed in M9) and the Mac-side Python tools were out of scope.

Reviewed, in order: sockets on shared rings (`user/include/sockring.h`,
`user/lib/sockring.c`, netstack's `sock.c`/`clients.c`/`sockmem.c`/`progs.h`
and the fair shares); TCP in netstack (`port/lwipopts.h`, `tcp.c`, `stack.c`'s
TCP edge, `tcpsock.c`, window scaling, bulk rings); `serve` and `<http.h>`
(`user/services/serve/`, `user/lib/http.c`, `httpchunk.c`); `fetch`
(`user/apps/fetch/`); the listen and low-port permissions (`user/lib/wants.c`,
`tools/checkwants.py`, `user/services/shell/sh_allow.c`, netstack's
`listen.c`); init's async netstack calls and the netif event fix
(`user/services/init/net.c`, netstack's `netif.c`); and the lead (a fat write
that waited 80 minutes past init's 120 s deadline).

Severity: **High** lets a frame leave outside the configured mode, lets the
network or a program reach what it should not, or corrupts memory; **Medium**
is wrong behaviour the owner will meet, or one client's trouble holding up
others; **Low** is a narrow case, a wart, a gap in a check, or a rule of the
guide broken.

**Nothing High or Medium was found.** What held up under a careful read:

- **The ring trust model** (`sockring.c`, `sock.c`, `tcp.c`). netstack keeps
  its own counts and copies and never reads its own lines back; the program's
  count is read once per look and clamped (`sockring_ready_n`/`sockring_room_n`
  reject a count that went backwards or runs more than a ring ahead, each
  counted); a record's 16-byte header is read once as two atomic words and
  checked on the copy, with the record bounded against what was published; the
  datagram header never straddles the ring's end (`SOCKRING_MIN % SOCKRING_ALIGN
  == 0`, records 16-aligned, count always 16-aligned); bytes are copied out
  before use; bytes after `SOCKRING_END` are ignored; a broken ring is looked
  at only on the program's next signal (`to_stack` PERSISTENT), so garbage
  costs one look per signal, not one per turn. A hostile ring hurts only its
  own socket; the VMO is shrunk to 0 on close so no page charged to netstack
  outlives the socket.
- **The fair shares** (`clients.c`, `sockmem.c`, `tcpsock.c`). The class is
  fixed at connect by the shared channel (`struct opener_kind`), never by
  anything the opener says. Ordinary openers (`CLASS_PROG`) are bounded by
  `NET_PROG_*`; the rest is a reserve only `CLASS_SYS` can use, and `/svc/net-sys`
  is reachable only by a boot-image service (`tools/checkwants.py` allows it
  only under `user/services/`, `allow` refuses it for `/data`). Ring-byte
  accounting is symmetric across socket close, opener-gone-but-socket-kept and
  TCP close-opener (the opener's count drops with it, the class's once, on the
  program's final close): no double-count or leak that would loosen a limit.
- **TCP's checks lwIP lacks** (`stack.c` `tcp_drop`): the RFC 9293 3.10.7.4
  no-ACK drop and the RFC 5961 §5 blind-injection ACK-window check run before
  lwIP sees a segment; ISNs come from the kernel CSPRNG (`lwport_tcp_isn` ->
  `os_random_u32`), not lwIP's guessable counter. SYN floods and closing pcbs
  get the lowest priority, so the pool recycles them before a program's
  connection; netstack's own counts, not the pool, bound programs.
- **Window scaling and bulk rings.** The announced window is the rx ring's
  room, capped at `TCP_WND` when the peer scales and `STACK_TCP_WND_PLAIN`
  when not (`window_set`), set only after the SYN/SYN-ACK settles scaling, and
  counted in 64-byte units (shift 6), so it never exceeds the ring. lwIP's
  heap is shared out (`stack_tcp_room`/`shares_room`) so TCP never takes the
  last `STACK_HEAP_KEEP`, and a bulk sender's bytes past its first 64240 never
  the bulk reserve: a slow or zero-window peer holds no more than its own
  window, out-of-order floods are dropped (no OOSEQ queue), and nothing a peer
  sends pins a receive buffer.
- **`serve` and `<http.h>`.** The head parser is strict and bounded (≤16 KiB
  head, 64 lines, CRLF/LF only, no obsolete folding, tokens checked, decimals
  that can't overflow, Content-Length/Transfer-Encoding must agree); a bad or
  oversized request is answered 400/431/501/505 and the connection closed, not
  guessed at. The server reads only the one file the shell handed it and serves
  it to every path asked — nothing from a request is ever opened or looked up.
  Each client has a head/idle/keep/close deadline; slots, per-share clients and
  shares are capped; the log is rate-limited. `/svc/serve` and the low-port
  permission are refused to `/data` programs (`sh_allow.c`, `checkwants.py`).
- **`fetch`.** A hostile server can't crash it or overrun a buffer: the head
  is bounded by a static 16 KiB buffer and `HTTP_HEAD_MAX`, the body by
  Content-Length / `http_chunks_step` / the connection's end with bytes past a
  length ignored, every wait has a deadline (name, connect, head, idle) and the
  stop channel in the wait set, redirects are capped at 3 and only to
  `http://`. The `.part` file is renamed into place on success and unlinked by
  the shell on any failure or stop, so nothing is left behind.
- **init's async netctl calls and the netif fix.** `set_ipv4`/`set_dns` go with
  `_send` and their answers are taken from init's port (`KEY_NETCTL`), one
  reader, with a 1 s "overdue" note and a resend on the next netstack start or
  `/data`; a stopped DHCP client's end is awaited on the loop, not inline. The
  `to_stack_event` fix clears only the bits it acts on and rebinds ONCE, so a
  link or tx-room change signalled between the fire and the rebind is not lost.

## Findings

| # | Sev | Where | What |
|---|-----|-------|------|
| 1 | Low | `user/services/init/net.c:414` (`net_given_up`) | When netstack is permanently given up, `net_given_up` closes the `ctl_srv`, `net_srv`, `listen_srv` and `sys_srv` server ends but not `low_srv` (`/svc/net-low`, SR_USER + 4), which was added later. The client end is still unpublished (`services.c` publishes `SVC_NET_LISTEN_LOW` invalid on give-up), so this is a one-handle leak in init on a terminal path and an inconsistency with its three siblings, not a reachability bug. |
| 2 | Low (lead, not a bug) | init's update write path (`espwrite.c`), `kernel/object/channel.c:577` | The lead's `prev-jamos.elf.new: 0 of 3888 KiB written in 4786031 ms (ERR_TIMED_OUT)` is **not** a deadline failure. The deadline is passed through (`until(w)` -> `file_*_until`/`fs_*_until` -> `channel_call`'s `deadline_ns`) and honoured (`channel_call` returns `ERR_TIMED_OUT` once `uptime_ns() >= deadline_ns`), and the user clock base matches the kernel's (`now()` = `jam_clock_get()` = `sysc_clock_get` = `uptime_ns()`). 4786031 ms is the Mac host sleeping: pmset logs `2026-10-03 15:14:53 Entering Sleep state due to 'Low Power Sleep' ... 4786 secs` at 1% battery, which froze the QEMU guest mid-`file_write`; on wake the guest TSC had jumped ~4786 s past the 120 s deadline, so the next `channel_call` iteration timed out at once. The write stopped correctly; only the elapsed-time figure in the log is a frozen-clock artifact. No code change. |
| 3 | Low (design, as built) | `user/services/netstack/stack.c:255` (`tcp_drop`) | Every inbound IPv4/TCP frame walks `tcp_active_pcbs` once before lwIP (for the no-ACK and RFC 5961 checks). The list is bounded by the pcb pool (256 connections + 128 half-open/closing) and the per-turn rx budget, and it is the same order as lwIP's own delivery lookup, so it is not a new amplification. Noted for the owner, no change. |
| 4 | Low (design, as built) | `user/include/net.h`, `clients.c` | One program opening many openers can take a whole `CLASS_PROG` share of netstack's openers/sockets/requests/ring bytes (netstack knows channels, not senders). This is the documented M9 design limit (question B, deferred); the `CLASS_SYS` reserve, reachable only by boot-image services, is what protects dns/netlog/sntp/update. No change. |

### Design questions for the owner

- **A (finding 4).** Sharing the per-class limits per program needs a notion of
  "program" the IPC deliberately doesn't have. M9's review deferred this
  (question B) past M9; M9.5 keeps it deferred. Nothing to decide unless the
  owner now wants per-program fairness within a class.
- **B (finding 3).** The pre-lwIP per-frame pcb scan is cheap today. If the PC
  ever shows TCP-flood CPU in `net stats`, a small hash by (local port, peer)
  would remove the walk; not worth building before a measurement says so.
