# M8.6 plan: cleanup and polish

Goal ([roadmap](../ROADMAP.md#later)): **tidy what M8, the audio track and
M8.5 left, make the everyday system feel finished, and put the
permission and service model networking will build on in place.** The
code check against the guide comes last, so it covers M8.6's own
changes too.

**Done when:** the boot log's own line says the keyboard and mouse were
ready within about 2 s of the kernel's start; the code check's findings
are fixed or written into the guide; on the PC, All tests and `soak 10`
with the SanDisk mounted read-write and pulled and replugged once.

## The owner's decisions (2026-10-01)

1. **Programs from `/data` run only once the owner marks them**, from the
   shell (`allow`, below). Marking needs a capability only the
   interactive shell holds, so a program can never mark a file itself.
2. **The splash always plays to its end.** No key skips it, Esc
   included; keys typed meanwhile are queued for the shell.
3. **`/svc` with per-program views.** Services are names under `/svc/`;
   each program sees only the names and mounts it was granted.
   **A program declares what it wants** (a list carried in the file) and
   the owner approves it when marking it runnable:
   `allow jamjar: music, mixer, /usb0 (read)? y/n`. Programs in the boot
   image are approved by the build. A program that asks for nothing gets
   its terminal (screen and keys) only. Approvals live on `/data`
   (`/data/etc/allow`); `allow -l` lists them, `allow -r <name>` revokes.
4. **Untrusted files are decoded in small programs of their own.** `play`
   becomes its own program holding only its file and a sound output;
   jamjar's covers go to a helper that holds only the picture's bytes and
   returns pixels.
5. **The small items, all in:** Ctrl+Alt+Del's 6 s wait, the boot disk
   taken from what Limine booted, `make flash` writing new names then
   renaming, a bigger kernel log ring.
6. **The screen:** the kernel log stops printing into the shell, and the
   RESULTS boxes leave normal boots (the test entries keep them). A short
   list of notices still reaches the shell, only where they are useful
   (a stick removed, a service that crashed and came back, `/data` full).
7. **The block cache is write-through**: sticks get pulled.
8. **Also before networking:** the real date and time (from the RTC: file
   dates on the sticks, dated logs), the root resource's `RIGHT_READ`
   split into what each user needs, and a settings file that survives a
   reboot.
9. jamjar's covers stay one per album.
10. **The docs check's candidates are in too**
    ([M8.6-CANDIDATES.md](M8.6-CANDIDATES.md), its top twelve):
    placed in the tracks below and marked *(candidates)*.
11. **The approvals file and the stick:** `/data/etc/allow` can be edited
    on any other computer the stick is put into. That opens nothing new:
    whoever holds the stick can already replace the kernel on it. The
    approvals guard against programs running inside Jam OS, which is
    their point; ARCHITECTURE says so.

## The work, in order

**0. The independent review of M8.5's code** (kernel/kexec, kernel/boot,
the panic path, init's reboot and last-boot paths, logd's crash file),
by an agent that did not write it: findings first, then fixes with tests
(the standing rule). *(candidates)* With it: the stored kernel's region
from 128 MiB to what it needs with room (about 32 MiB, measured), and
the boot entry "Jam OS (Limine starts the CPUs)" removed now that the
kernel's own startup is signed off (the `smp=loader` word can stay for
troubleshooting). It merges before the tracks below start their
final test rounds.

Then three tracks in parallel, each in its own worktree. The files each
owns are listed; an edit outside them is kept minimal and named in the
report.

### Track A: USB, storage and boot

- **Input early in boot.** usb-bus answers the HID drivers as soon as
  each device is configured (not after every port); root ports reset and
  devices are set up in parallel, so one slow device delays only itself;
  the gaming mouse's (258a:0033) refused Address Device, which costs
  3.2 s today, gets short backing-off retries and its cause found; the
  boot timer self-check (1 s of waiting before user space) leaves the
  normal boot path (the test entries keep it, or it runs in the
  background). A boot-log line says when the first keyboard and mouse
  were ready.
- **Keys during the splash** are queued for the shell (the console), with
  no key skipping the splash (decision 2).
- **The block cache** in fat, write-through, with reads of many sectors
  per request (the ESP's one-sector clusters make `reboot`'s file read
  slow today), and one copy fewer in usb-storage.
- **The boot disk** is the one Limine booted from (its MBR disk id), not
  the first with the layout.
- **Ctrl+Alt+Del:** the console stops taking keys once it has asked for
  the reboot, so the keyboard drivers don't wait on it.
- **`make flash`** (tools/flash-usb.sh) writes the files under new names
  and renames them, so a pull at any moment leaves a stick that boots.
- **A bigger kernel log ring** (1-4 MiB), so a burst or a missing stick
  loses nothing. *(candidates)* The klog flood ktest writes the ring's size
  and more: bound what it writes (or skip it live) so a live ktest or a
  soak loop doesn't put megabytes of filler into `/data/logs`; `dmesg`,
  `KLOG_READ_MAX` and the texts that say 64 KiB follow the new size.
- *(candidates)* **devmgr's false "did not end cleanly"** (the PC's HAF700
  hid after a warm reboot: a request left queued at usb-bus still charged
  to its job): a second look before counting it, so it never becomes a
  false notice on the screen.
- *(candidates)* **The `init` QEMU run's flake** (about one run in three:
  fat-esp still mounting when devmgr shuts down after usbtest restarts
  usb-storage).
- *(candidates)* **FAT directory listing is quadratic** (each entry found
  again from the start); the music scan and jamjar's library walk the
  owner's 93 albums with it. Linear, with a test that times it.

Owns: drivers/usb-bus, drivers/hid, drivers/usb-storage,
user/services/fat, devmgr's disk and USB code, the console's input
path, kernel/debug/klog.c's ring size, the timer self-check's place in
kmain, tools/flash-usb.sh.

### Track B: `/svc`, permissions and the splits

- **`/svc`** in the namespace: init publishes its services (music, mixer,
  devmgr, logd's control, ...) as names; a program opens them like files
  instead of receiving a fixed startup set. The shell's startup-handle
  limit goes away.
- **Per-program views and the program's list.** A program's file carries
  the list of what it wants (services, mounts, read or write); the
  namespace a program gets is exactly what was granted. Boot-image
  programs are granted by the build.
- **`allow`** in the shell: marks a program on `/data` runnable and grants
  its list after the owner's yes (decisions 1 and 3), stored in
  `/data/etc/allow`; `-l`, `-r`. Running code from `/data` needs both.
- **The splits:** `bin/play` with only its file and a sound output (the
  shell's `play` starts it); jamjar's cover decoding in a helper with only
  the picture's bytes.
- **`RIGHT_READ` on the root resource split** into the kernel log, the
  serial port, the process list and the clock, each given only where
  used. *(candidates)* **And `RIGHT_MANAGE`**, which today covers
  `debug_command`, the `reboot` syscall, `kexec_load` and `kexec_reboot`
  (the shell could load and start any kernel file): split so reboot,
  loading a kernel and debug commands are separate rights, each held only
  where needed (`kernel load` in track C uses the kexec one through init).
- *(candidates)* **hda's channel only to the mixer:** today any caller of
  devmgr's `GET_SERVICE` gets it (the shell's `hda` and hdatest can take
  the one output stream and starve the mixer). The shell keeps `hda`'s
  read-only queries.
- *(candidates)* **Each program its own music channel** through `/svc`
  (jamjar shares the shell's endpoint today, so a cut-short call leaves
  late answers in the shell's job).
- *(candidates)* **init waits for the splash with a deadline** (no key can
  skip it now: a hung splash must not keep the shell away). The video's
  length plus a margin, then the shell starts anyway and says why.
- *(candidates)* **init/shell.c split first** (866 lines, over the
  guide's 800), as a behaviour-preserving commit, before the track's
  changes to it.

Owns: user/lib/ns.c and the namespace protocol, init's service
publishing and startup, the shell's program start (sh_program.c) and
the new `allow`, the startup roles, user/services/shell/cmd/play.c and
the new bin/play, jamjar's cover.c and the new helper, the kernel's
resource rights.

### Track C: the everyday polish

- **The log off the screen** and the RESULTS boxes off normal boots
  (decision 6), with the short list of notices; `verbose`, `nosplash`
  and the "text log" entry show everything as today.
- **UTF-8 through the kernel log** (well-formed only; controls and
  malformed bytes still replaced), so "JAŸ-Z" is not "JA??-Z".
- **`kernel load`**: reads `/esp`'s kernel and boot image into the stored
  slot now and says whether it loaded, so a flashed stick can be loaded
  before the reboot (instant then; a panic also comes back in the new
  build).
- **The real date and time:** the RTC read at boot, the time kept by the
  kernel's clock; fat stamps files with it (the Mac sees real dates);
  each log file starts with the date and time. *(candidates)* The
  calendar and time-zone code moves from the shell (sh_time.c) to libos.
  The kernel keeps UTC; FAT stamps and what is shown are local time, the
  time zone a setting (`/data/etc/settings`, default the owner's,
  Australia/Sydney with daylight saving).
- **Settings that survive a reboot:** `/data/etc/settings` (plain text,
  one `key = value` a line): the master volume, the music folder and the
  player's volume to start with; read by init, written by `vol` and
  `music` when they change something; M9 keeps its network settings
  there.

Owns: the console's output path and its notices, kernel/debug/klog.c's
text handling and the screen echo, logd's file header, init's settings
and the `kernel load` command, the RTC (kernel/dev/rtc.c) and the clock,
fat's timestamps (one function, agreed with track A).

### Last: the code check

Fresh agents, one each for the kernel, the drivers, user space, and the
tools and tests, check everything against CODING-GUIDE.md and
ARCHITECTURE.md, M8.6's changes included. Findings only, written down
first; the owner and the main session sort them (the code is wrong, or
the guide should change); then fixes in batches, behaviour-preserving
ones apart from the rest.

## Where tracks meet

- **The shell** (B: program start, `allow`; C: notices, `kernel load`):
  separate files; the command table is the one shared line.
- **devmgr** (A: the boot disk, USB; B: publishing under `/svc`): A owns
  disk.c and usb.c, B the publishing.
- **fat** (A: the cache; C: timestamps): C adds one function to fat's
  time source; A owns the rest.
- **init** (B: services and views; C: settings, `kernel load`): separate
  files.
- Merge order: the M8.5 review, then A, B, C as they finish; the code
  check after all three.

## After the code check: the pre-M9 batch (the owner, 2026-10-02)

The architecture check ([ARCH-CHECK.md](ARCH-CHECK.md)) and the
code check's design questions, decided by the owner, done before the
sign-off soak:

- **Service loops** (ARCH-CHECK 0/8, 7): the rule that a loop serving
  several clients never blocks on a call inside a request, written into
  CODING-GUIDE and ARCHITECTURE; genidl gains deferred replies and
  asynchronous calls; usb-bus's cooperative tasks (task.c) become a libos
  library other services can use.
- **Device-scoped channels** (ARCH-CHECK 2): a devmgr channel scoped to one
  device, made by init (hda's to the mixer; the NIC's to netstack at M9),
  replacing the exclusive flag and the SR_DEVMGR_AUDIO role. With it each
  opener its own channel to audio, audioctl, devmgr and logd (services
  check D5) and a per-client stream cap in the mixer (D6).
- **Kernel:** a VMO sealed by vmo_make_exec (no write or writable mapping
  can land after it; krest 16); framebuffer_take and serial_write get root
  rights of their own (krest 17); the kernel stamps each log line with the
  writer's process id, so the console's notices trust only init's,
  devmgr's and logd's real lines (services D3).
- **Programs from /data are refused `right debug`** (services D2), and init
  never gives up restarting the console or the shell (D7).
- **jamjar:** a cover decode that timed out is retried once (libs 18);
  libfun's drawing calls move to a `struct rect` gradually (libs 16).
- **Docs:** driver isolation stated honestly until the IOMMU (ARCH-CHECK
  3/5) with a "what Jam OS defends against" paragraph; the stale lines it
  lists; its ROADMAP changes; the finished plans (A1, A2, AS, M8.5) moved
  to docs/history (libs 12), last.
- **The sign-off** then: All tests, `soak 10` with the SanDisk pulled and
  replugged, and `bench` on the PC for BENCH.md (ARCH-CHECK 4).

Left for later (the owner): porting `lite`, a screen recorder from boot,
the terminal layer in M13.
