# M8.5: the kernel starts its own application processors

Half of M8.5 ([ROADMAP.md](../ROADMAP.md)). After a kexec there is no
Limine, so the kernel must wake the other CPUs itself with the INIT-SIPI-SIPI
protocol. To have one path for every boot, the kernel's own startup becomes
the default under Limine too; Limine's release of its parked CPUs stays
behind the boot word `smp=loader` until the owner signs the new path off on
the PC.

References: Intel SDM vol. 3A (the 2024 edition's numbering), chapter 9
"Multiple-Processor Management" (9.4 "Multiple-Processor (MP)
Initialization", 9.4.4.1 "Typical BSP Initialization Sequence"); chapter 10
"Processor Management and Initialization" (10.1, Table 10-1, the
processor's state after power-up, reset or INIT); chapter 11 "APIC" (11.6.1
"Interrupt Command Register", 11.12.5.1 "x2APIC States"); chapter 12
"Memory Cache Control" (12.11.8 "MTRR Considerations in MP Systems").

## What the BSP does

1. **At early boot** (`apboot_reserve`, right after `pmm_early_init`): take
   one page of the memory map's usable RAM in [64 KiB, 640 KiB), the
   highest one, out of the early allocator, so the buddy allocator never
   sees it. It is the trampoline page for the whole boot and is never
   given back. Why these bounds: a SIPI's 8-bit vector starts the AP at
   vector x 4 KiB in real mode, so the page must be below 1 MiB; 640 KiB
   and up is the VGA hole and ROMs (and SIPI vectors A0h-BFh are reserved);
   below 64 KiB some firmware is known to scribble (BIOS data area, SMM
   handlers on old boards; Linux keeps it reserved for the same reason).
   No hardcoded address: if the memory map has no such page, the kernel
   says so and runs on the BSP alone (or uses the loader, if it can).
2. **Before the startup** (`apboot_prepare`): copy the trampoline into the
   page through the HHDM and fill in its data block (its own GDT, the far
   pointers relocated to the page's address, the CR3 and EFER to load, the
   kernel entry address). Build a **transition page table** in four pages
   below 4 GiB: a PML4 whose kernel half (entries 256-511) is copied from
   the kernel's PML4 (the kernel-half PDPTs are shared and never freed,
   which is how every address space shares them), plus PDPT, PD and PT
   that map exactly one 4 KiB page, the trampoline, at its own physical
   address. It is separate from the kernel's PML4 because CR3 is loaded in
   32-bit mode, so it must be below 4 GiB, and because the kernel's PML4
   never gets a user-half mapping, not even for a moment. Fill a slot per
   AP: its APIC ID, its kernel stack top, its struct cpu.
3. **The IPIs** (`apboot_kick`), per CPU from the CPU list (not a
   broadcast), in three passes so that all CPUs start in parallel while
   each one still sees the SDM's timing:
   - INIT (level assert) to every AP, then wait 10 ms (9.4.4.1);
   - SIPI with the page's vector to every AP, then wait 200 us;
   - SIPI again to every AP that has not checked in, then wait 200 us.
   x2APIC: one `wrmsr` to the ICR MSR 0x830 with the destination in the
   high half. xAPIC: ICR high then low, each send waiting (bounded) for the
   delivery status to go idle; a CPU whose APIC ID does not fit xAPIC's 8
   bits is reported and not started. INIT level de-assert is not sent:
   processors since the Pentium 4 don't support it (11.6.1). After the
   passes the error status register is read and any error is logged. The
   delays use `udelay`, which counts the TSC calibrated against the HPET
   (or the PM timer). The whole startup costs ~10.5 ms however many CPUs
   there are.

   **Why per CPU and not broadcast "all excluding self"**: a broadcast also
   wakes CPUs the firmware disabled (the MADT can list a CPU as not
   enabled: hyper-threads switched off, a faulty core fused out) and
   CPUs the kernel does not want (beyond `MAX_CPUS`). Targeting each listed
   CPU is what the SDM's own MP example does once the BSP has its list.
4. **Waiting**: up to 1 s for every AP to claim its start (below). Then,
   for every AP that did not, the BSP takes the CPU's start state from
   STARTING to ABANDONED with one compare-and-swap, sends it INIT (which
   stops whatever it is doing and leaves it in wait-for-SIPI, where it
   takes no interrupt and no NMI, so even the panic path's NMI to all
   other CPUs cannot reach it), and logs `smp: lapic L (cpu list entry N)
   did not start`. The BSP never hangs on a CPU. This is the same on the
   Limine path.
5. **Afterwards** (`apboot_finish`): if any CPU was abandoned, wait another
   10 ms so its INIT has certainly landed; then overwrite the trampoline
   with a three-instruction stub (`cli; hlt; jmp` back to the `hlt`), free
   the transition tables, and clear the slots. The page itself stays
   reserved: a stray SIPI later only parks the CPU it wakes.
6. **Numbering**: the CPUs that claimed get dense indices 1..n-1 in list
   order (`renumber`), so a CPU that did not start leaves no hole in
   `cpus[]`: run queues, per-CPU arrays and the tests that pin a thread to
   every CPU see only CPUs that run. A stopped CPU's struct cpu and stacks
   stay allocated and unused. Then the BSP lets the claimed APs go on and
   waits (bounded) for them to come online. The RESULTS box gets
   `smp: N of M CPUs did not start` and the run counts as having
   problems.

## What an AP does

The trampoline (`kernel/arch/x86_64/trampoline.S`, one 4 KiB page, starts
at offset 0 because the SIPI starts the AP at CS = vector << 8, IP = 0):

- **16-bit**: `cli`, `wbinvd` (INIT leaves the caches and CR0.CD/NW as
  they were, a reset sets CD and NW; the write-back before CR0 is
  rewritten is what Linux's trampoline does too), DS = CS, EBX = the
  page's physical address, `lgdtl` the trampoline's GDT, CR0 = PE only
  (CD and NW clear: caches on), far jump to the 32-bit part.
- **32-bit**: flat data segments, CR4 = PAE, CR3 = the transition PML4,
  EFER = LME, and NXE when the CPU has NX (the kernel half's leaves use the
  NX bit, which is a reserved bit while NXE is off), CR0 = PE | PG | WP
  (long mode active; the trampoline is identity-mapped, so the next
  instruction is still found), far jump to the 64-bit part.
- **64-bit**: jump to `ap_boot64` in the kernel image (high half).

`ap_boot64` (kernel text): loads the kernel's own CR3 (from now on the
transition tables are not used, and with CR4.PGE off the CR3 write drops
every entry they put in the TLB), reads its APIC ID from CPUID (leaf 0Bh
when it has one, else leaf 1; CPUID works in either APIC mode), finds its
slot, switches to the slot's kernel stack, and calls `ap_boot_main`. A CPU
that finds no slot parks itself (`cli; hlt` forever).

`ap_boot_main` (C): `cpu_enable_paging_features` (NXE, WP, PGE, the PAT,
the same as the BSP), then the path both startups share, `smp_ap_main`:
`percpu_load` (its GDT/TSS, GS, the IDT, SMEP/SMAP/UMIP, PCIDs, the FPU,
SYSCALL), `lapic_init_cpu` (x2APIC: INIT keeps the APIC's mode and ID,
11.12.5.1; an AP whose mode differs from the BSP's is switched), the
topology, then **the claim**: a compare-and-swap of its start state from
STARTING to CLAIMED. If the claim fails the BSP has already given up on
it: the CPU parks itself (and the BSP's INIT resets it anyway). So an AP
that starts late writes only its own struct cpu (which the BSP never
frees) and its own registers before it learns it is too late. After the
claim it waits for the BSP's numbering, then runs the consistency checks
below, starts its timer and counts itself online. The Limine path goes
through the same claim.

## State the AP gets, and what is checked

INIT resets CR0 (but CD/NW), CR3, CR4, EFER, the GDT/IDT registers, the
APIC's registers (but not its mode or ID), and leaves the caches, the
MSRs in general, the MTRRs, the microcode and the TSC as they were (10.1,
Table 10-1). So:

- CR0, CR4, EFER, GS, the GDT/TSS/IDT, the PAT, PCIDs, the FPU/XSAVE and
  SYSCALL MSRs are all set by the same functions that set the BSP's.
- **MTRRs**: firmware programs every core's MTRRs the same at power-on, and
  INIT keeps them on real CPUs. Each AP compares its MTRRs (default type,
  the fixed ranges, every variable pair) with the BSP's snapshot (12.11.8
  requires them to match) and, if they differ, loads the BSP's with the
  SDM's procedure for one CPU (12.11.7.2: no-fill cache mode, write-back,
  TLB flush, MTRRs off, write, write-back, flush, MTRRs on), as Linux does
  for every AP. QEMU's TCG does reset the MTRRs on INIT, so in QEMU every
  AP takes this path (`smp: N CPUs had MTRRs other than the BSP's: set to
  the BSP's`); on the PC it should not run. MTRRs of a different layout
  (another count of variable ranges) are only reported.
- **Microcode**: firmware loads it on every core. Each AP reads its
  revision; a revision different from the BSP's is logged (the PCID
  erratum decision is made from the BSP's).
- **TSC**: the kernel does no TSC synchronisation (it relies on the
  invariant TSC, which firmware starts in step). INIT does not touch the
  TSC. Each AP compares its IA32_TSC_ADJUST (when the CPU has it) with
  the BSP's; a difference means firmware moved one core's TSC, and is
  logged.
- One summary line: `smp: every CPU matches the BSP (microcode 11f,
  MTRRs, TSC_ADJUST)` (with "now" after BSP when MTRRs were loaded), or
  the lines that differ.
- **Hybrid P/E cores**: nothing in the protocol differs between them;
  `cpu_detect_topology` runs on every CPU as before.

## Fallbacks and boot words

- `smp=loader`: Limine releases its parked CPUs (`boot_start_cpu`), as
  before. A CPU without a loader handle (a kexec'd kernel) cannot be
  released that way: then the kernel's own startup is used and the log
  says so.
- No trampoline page: the loader's release if there is one, else the BSP
  alone, logged.
- Loader memory is reclaimed only when every CPU came online, as before
  (a CPU that never answered might, in principle, still be in Limine's
  code).
- Not built: the trampoline page is not handed back after the startup (4
  KiB), and a CPU that did not start is not retried (no CPU hot-plug).
- **For the kexec side** (the other half of M8.5): the kexec'd kernel
  needs a usable page in [64 KiB, 640 KiB) in the memory map it is given,
  and `cpus[]` with `lapic_id`s. The CPUs may be in any state: INIT resets
  them. One suggestion for the join: before jumping, send the stopped CPUs
  INIT (`lapic_send_init`) rather than leaving them in a `hlt` loop in the
  old kernel's memory, which the new kernel will overwrite: a halted CPU
  can still be woken by an SMI that resumes after the `hlt`, an NMI or a
  machine check (Linux parks CPUs in INIT before a kexec for this reason).

## Tests

- ktest `smp_trampoline_parked`: the page is below 640 KiB and above
  64 KiB, still reserved (not in the allocator), holds the park stub; the
  transition tables are freed; the kernel PML4's user half is empty and
  the trampoline's physical address is not mapped there.
- ktest `smp_cpus_match_bsp`: on every online CPU (a cross-CPU call)
  CR0, CR4, EFER, the PAT, the APIC ID, the GS base and the MTRR default
  type are what the BSP expects.
- Boot words for the failure paths, ktest kernels only:
  `smp_test_late=<cpu>` makes that AP wait in `smp_ap_main` until the BSP
  has given up on it, then try its claim (which must fail and park it);
  `smp_test_skip=<cpu>` sends that CPU no IPIs at all. Each boot must
  log the CPU as not started, run with one CPU fewer (numbered densely),
  and pass the kernel tests; its RESULTS box says FINISHED WITH PROBLEMS.
  Both on the kernel's own startup and on `smp=loader`.
- QEMU (TCG, as the harness uses) at 1, 2, 4, 8, 16 and 28 CPUs, x2APIC and
  xAPIC (`QEMU_CPU=max,-x2apic`), and `smp=loader`; then the full
  regression of [TESTING.md](../TESTING.md).

## What only the PC can prove

- That INIT-SIPI-SIPI wakes all 28 CPUs (P- and E-cores) on the real board:
  `smp: 28 of 28 CPUs online` with the startup's time in the same line,
  and no `did not start`.
- `smp: every CPU matches the BSP` (real MTRRs, microcode, TSC_ADJUST;
  QEMU has none of that variety).
- The boot time difference between the default and `smp=loader`.
- The timer report (`timer: ... all ok`) and the topology line after the
  new startup, and All tests + `soak 10`.
