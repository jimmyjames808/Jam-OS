# M8.6 code check: libraries, apps, tools and docs

The last step of [M8.6](M8.6-PLAN.md#last-the-code-check): a fresh read
of `user/lib` (libos), `user/apps` (libfun and the apps), `user/include`,
`user/tests`, `tools/`, the Makefile and the docs against
[CODING-GUIDE.md](../../CODING-GUIDE.md) and
[ARCHITECTURE.md](../../ARCHITECTURE.md), at main febd124. Findings first;
each one's outcome is filled in as it is fixed.

Severity as in the other reviews: **High** is a program reaching what it
should not, or memory corrupted by input; **Medium** is wrong behaviour a
user will meet, or a test or build that fails for a reason that is not
the code's; **Low** is a wart, a narrow race or a guide rule broken.

What held up (read with untrusted input in mind): `wav.c` (every chunk
read through the callback with its length checked, the data chunk cut to
the file), `mp3.c`'s sniffer (ID3v2 sizes, APE and ID3v1 footers, the
frame walk inside its 8 KiB window), `play_src.c`, `wants.c` (every
offset and note length checked before it is read; a list is printable
ASCII and every line known), `settings.c` (lines bounded, values checked,
the write cut short leaves `settings.new`), `utf8.c` (Table 3-7),
`wallclock.c`, `start.c`'s startup message, `ns.c`'s messages from the
starter, `fsview.c` (with fat's own name check behind it: a backslash or
trailing dot that FatFs would read differently is refused by fat first),
`fs.c`, `spawn.c`, `heap.c`, `printf.c`, jamjar's `id3.c` and
`decoder.c` (the helper's answer is range-checked, its pixels only ever
read with `vmo_read`), and bin/jamcover (sizes checked before stb_image
decodes anything).

## Outcomes

- **1 fixed** (ee6c53a). The copies are named in static pattern rules,
  not `.SECONDARY` patterns (`build/uinc`, `build/driver-include`,
  `build/fatfs`). Test: the reproduction by hand (no test in the suite:
  it needs two builds across a commit that adds a protocol): built at
  8edeb93^ with the change, checked out 8edeb93, `make -j8`: done in
  about a second (before: still spinning after 120 s).
- **2 fixed** (3f14054). `pool_rest` (libfun): a worker that sees it
  since its last batch sleeps at once; `gfx_key` and `gfx_key_event` call
  it before they block, so every app's workers sleep while it waits for
  keys or its next frame, and batches that come back to back still find
  them awake. Test: life's self-test rests the pool and counts the pauses
  spun after it (FAILED before: 40000 for 3 workers; after: about 600).
  That count failed under host load (16900: the test's own thread off
  the CPU before the rest), so the test was made deterministic
  (166d433): `pool_set_spin(UINT32_MAX)` makes the workers spin until
  the rest, and all must be asleep within 5 s of it (without the rest: 0
  of 3 asleep, FAILED; with it: 3 of 3). On the PC: jamjar open should
  no longer cost ~3 CPUs (`top`).
- **3 fixed** (c0ca2b7). The stopped tone may be followed by no silence;
  instead its last sample must be the fade's end (2 % of its peak or
  less). Checked on a real capture cut both ways: ending at the fade
  (FAILED before, passes) and 100 ms early mid-tone (fails).
- **4 fixed** (e3793ba). checkdocs checks links and anchors in
  docs/history, not its spans. Test: a link to a missing file added
  there fails (passed before).
- **5 fixed** (1bd18a6). The Makefile links the player's `spectrum.c`
  and `tracks.c` objects into utest (`EXTRA_OBJS_utest`); utest/music.c
  includes `music.h`. The init run: utest's four music tests ok.
- **6 fixed** (5040782): `box_pixel()` and `cover()`, the same
  arithmetic in the same order.
- **7 fixed** (ee43a52). No test: the failures need the heap or the
  handle table full when an app starts.
- **8, 9 fixed** (cc66be5).
- **11 fixed** (f19804e). `lock_take`/`lock_give` in libos (`lock.c`,
  `<os.h>`): 64 pauses, then 20 us sleeps; the heap, ns.c's two locks and
  jamjar's two use it; the guide names it under "Shared helpers live
  once". Test: utest `lock_take` (6 threads x 20000 increments with
  holders sleeping now and then: none lost). That a waiter sleeps is a
  scheduling property with no practical test.
- **13 fixed** (67482b4), with ARCHITECTURE's libfun paragraph (the
  pool's rest).
- **14 fixed** (c54f579). A failed file call whose filesystem service is
  still there 30 s later is FAILED; a pull (the service ends) or a full
  volume (`ERR_NO_SPACE`) is cut short. No failing test is practical: no
  live service fails file calls in QEMU on purpose. In soak-test the one
  call the two pulls cut short is still cut short (441 cycles, 0 FAILED).
- **15 fixed** (1160bdc).
- **17 fixed** (b2aa2ba). Both run QEMU with `-trace hda_audio_overrun`;
  each traced drop excuses one click or one sound up to 2048 frames
  short, and says so. Checked on the two failed captures: they fail with
  no drop traced and pass with one; both tests pass again on a quiet host.
- **19 fixed** (75beb48): tried again after 2 s when it fails.
- **Not fixed** (reported): 10 (narrow; a fix needs a reference count or
  a per-thread copy of the handle), 18 (a design question), 12 (moving the finished plans touches
  every area's comments: after the check's branches merge), 16 (a design
  question).

`make KTESTS=0`, two clean `make -j8` (no spin), ktest (248 passed), the
