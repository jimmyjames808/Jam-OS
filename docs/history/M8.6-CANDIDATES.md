# M8.6 candidates: what the docs and the code leave open

A list made on 2026-10-01 (main at 109c855) while checking every document
against the code. It holds the known limits, follow-ups, "not yet"s,
workarounds, flakes and open design questions found in the docs and the
code that are **not** in [M8.6-PLAN.md](M8.6-PLAN.md). Nothing here is
decided: the owner and the main session sort it. The code has no `TODO`,
`FIXME` or `XXX` comments; every item comes from a document, a review's
unfixed findings, or a reading of the code next to a document.

Each item: where it is, what it is, why it might matter, a rough size
(small: an hour or less; medium: a few hours; large: a milestone's
track), and where it fits. M8.6's theme is cleanup, polish, permissions
and what networking will build on.

## Fits M8.6

Most worthwhile first.

1. **`RIGHT_MANAGE` on the root resource is one right for four powers.**
   Where: `kernel/abi/sysc_console.c:5-13` (`debug_command`, `reboot`),
   `kernel/abi/sysc_kexec.c:27,53` (`kexec_load`, `kexec_reboot`); init
   gives it to the console and the shell (`user/services/init/shell.c:351,648`).
   What: the plan splits `RIGHT_READ` on the root; `RIGHT_MANAGE` has the
   same shape. Whoever runs the kernel tests or a deliberate panic can
   also replace the stored kernel with any image from a VMO it can read
   (a file on `/data`) and jump to it. Why: the shell decodes MP3s from
   any stick in its own process until track B's `bin/play` lands, and
   parses names and files from sticks after it; `kernel load` (track C)
   only needs `kexec_load` in init. Size: small to medium. Fit: track B,
   next to the `RIGHT_READ` split.

2. **The bigger log ring makes the klog flood test write megabytes.**
   Where: `kernel/test/test_console_svc.c:106` (`console_klog_read_after_gap`
   writes `KLOG_SIZE + 4096` bytes of filler). Also sized for 64 KiB
   today: `dmesg`'s help (`user/services/shell/sh_table.c:39`), one
   `klog_read` at most 64 KiB (`KLOG_READ_MAX`, `sysc_console.c:37`), the
   crash file "the last 64 KiB of the log" (HARDWARE.md). What: with a
   1-4 MiB ring each live `ktest`, and each soak loop, writes 1-4 MiB of
   filler into `/data/logs/` and still loses it ("[logd: N bytes ... lost]").
   Why: it slows the soak on the stick and fills the boot logs; the
   decision on skipping that test live (ROADMAP's follow-up) is due with
   the ring. Size: small. Fit: track A (it owns the ring size).

3. **init waits for the splash with no deadline.** Where:
   `user/services/init/shell.c:789`; the audio review's finding 8,
   not fixed. What: a splash that hangs without exiting never says
   `SPLASH_PLAYED`, so the shell never starts. Why: decision 2 takes the
   key skip away, so nothing the owner types can end a stuck splash
   either. Size: small (a deadline in init's loop). Fit: whichever track
   takes the splash's keys (A) or init's startup (B).

4. **hda's channel is still served to any `GET_SERVICE` caller.** Where:
   `user/services/shell/cmd/hda.c:105,194`, `user/tests/hdatest/main.c:95`,
   devmgr's `GET_SERVICE` (`user/services/devmgr/main.c:193`); A1-PLAN
   ("How A2 builds on it") and A2-PLAN ("Left for later") meant the mixer
   to be its only client. What: the shell can open the driver's one
   output stream and set the codec's gain; while `hdatest` holds the
   stream every mixer stream fails to start (`ERR_BAD_STATE`). Why: with
   per-program views the question "who may reach `hda`" gets an answer
   anyway. Size: small to medium (the shell's `hda` needs a read-only way
   to the dump and jacks). Fit: track B.

5. **jamjar shares the shell's end of the player's channel.** Where:
   `user/services/shell/sh_program.c:144-145` (`RUN_MUSIC`),
   JAMJAR-REVIEW finding 11 and design question C. What: a call cut short
   (jamjar quits or is killed mid-call) leaves the player's late answer
   queued on the shell's endpoint, which only ever calls on it: up to
   1024 messages kept in the shell's job. Why: `/svc` (track B) can give
   each opener a channel of its own; the music service must then hand out
   one per open rather than share. Size: small once `/svc` exists. Fit:
   track B.

6. **The calendar and time zones live only in the shell.** Where:
   `user/services/shell/sh_time.c` (civil dates, `$TZ` with Sydney's
   daylight rule, `$RTC=local|utc`). What: track C stamps FAT files and
   dates each log file, in fat and logd. FAT times are local time by
   convention, and the PC's RTC keeps local time (Windows sets it). Why:
   without a decision fat and logd get a second copy of the calendar or
   UTC dates the Mac shows shifted. Size: small (move it to libos; decide
   the zone fat and logd use, perhaps a `settings` key). Fit: track C.

7. **`hda gain` is not kept across a reboot.** Where:
   `drivers/hda/hda.h:431` (`GAIN_DEFAULT_CB`, -30 dB at every driver
   start). What: the plan's settings file keeps the master volume, the
   music folder and the player's volume, not the codec's level, which is
   the headphones' loudness. Size: small. Fit: track C, if the owner
   wants it.

8. **The `smp=loader` boot entry outlived its reason.** Where:
   `boot/limine.conf` ("the fallback until the kernel's own startup is
   signed off on the PC"), docs/history/M8.5-AP-STARTUP.md. What: the
   kernel's own startup was signed off on the PC with M8.5. Drop the
   entry (the boot word can stay for tests), or keep it and fix the
   comment. Size: small. Fit: track A.

9. **M8.5's region size is still the owner's open question.** Where:
   `kernel/include/jam/kexec.h:34` (`KEXEC_DEFAULT_MIB` 128), M8.5-PLAN
   ("As built", last item). What: the stored kernel needs about 12 MiB
   now that nothing runs in it; 128 MiB below 4 GiB stays reserved.
   Size: small (a number and the ktest that checks it). Fit: track A or C
   (`kernel load`).

10. **devmgr reports a hid that ended cleanly as "did not end cleanly".**
    Where: `user/services/devmgr/supervise.c:101,123`; ROADMAP follow-up,
    M8-REVIEW item 26; on the PC at most boots (the HAF700, 2516:01c1).
    What: a request the driver left queued at usb-bus is still charged to
    its job when devmgr checks it at the exit. Why: decision 6 makes "a
    service that crashed" a notice in the shell: this false one would
    show at boot. Size: small (a deferred second look). Fit: track A.

11. **The `init` QEMU run ends "with problems" about one run in three.**
    Where: TESTING.md "Known noise", ROADMAP follow-up. What: usbtest's
    last check restarts usb-storage, devmgr starts `fat-esp` again, and
    shutdown stops usb-bus while that fat is still mounting (it exits
    `ERR_IO`). Why: every track runs this test before it reports; a known
    flake costs each one a rerun and hides a real failure. Size: small
    (fat exits 0 when its disk goes while mounting, or devmgr excuses a
    filesystem whose disk went first). Fit: track A (fat, devmgr).

12. **`make -j8` can spin forever after a new file in `abi/idl/`.**
    Where: the Makefile's IDL rules (`IDL_OK`, line 92); M8-REVIEW item
    27, never looked into. Why: track B is likely to add a protocol for
    `/svc` or the cover helper. Size: small to look into. Fit: track B,
    or before the tracks start.

13. **init's `shell.c` is over 800 lines.** Where:
    `user/services/init/shell.c` (866 lines; ROADMAP lists only `vmo.c`,
    `sched.c` and `aspace.c`). What: one file holds every service's
    start, its handles and supervision. Why: track B rewrites init's
    service publishing and startup there; a behaviour-preserving split
    first keeps that diff readable. Size: medium. Fit: track B (a
    refactor commit before its changes).

14. **A FAT directory listing is quadratic.** Where:
    `user/services/fat/fsops.c:97` (readdir walks from the start for
    every index); M8-REVIEW item 21, AUDIO-REVIEW item 2. What: the music
    player's scan and jamjar's library read the owner's folders one
    index at a time. Why: the block cache makes each step cheaper, not
    the walk shorter; a few thousand files is where `music start` had to
    become stepped. Size: medium (a cursor kept per directory, or a
    readdir that returns many entries). Fit: track A (it owns fat).

15. **Names from someone else's stick reach the console as they are.**
    Where: `user/services/shell/cmd/ls.c`, `df.c`, `mount.c`, and
    `music status`; M8-REVIEW item 18. What: a crafted file name or
    volume label can carry escape sequences to the console. Why: track C
    decides what of UTF-8 passes through the log; the shell's own output
    of untrusted names wants the same rule. Size: small. Fit: track C.

16. **The mixer's ring and stream limits.** Where:
    `user/services/mixer/streams.c:20` (the ring handle's `RIGHT_WRITE`
    allows `vmo_set_size`: a client can grow it, charged to the mixer's
    job) and `:166` (any program can open all 16 streams, or fill the
    shared `SR_AUDIO` queue); AUDIO-REVIEW items 10 and 11. Why:
    per-program views give the mixer only to programs that ask; a cap per
    client and a ring the client can't resize close the rest. Size:
    small. Fit: track B.

17. **jamjar's cover limits.** Where: `user/apps/jamjar/cover.c:26`
    (1024 albums; the library holds up to 4096 files), `:178-182,393`;
    JAMJAR-REVIEW items 9 and 10. What: past 1024 albums the rest get no
    cover and each frame walks the full table; a file that can't be read
    once (the stick out for a moment) marks its album "no cover" until
    jamjar restarts. Why: track B moves the decoding into a helper; the
    table moves with it. Size: small. Fit: track B.

18. **libfun's pool spins about 1 ms after each batch.** Where:
    `user/apps/fun/pool.c:69,96-110`; JAMJAR-REVIEW item 14. What: jamjar
    runs two batches a frame at 60 frames a second, so about three of the
    PC's 28 CPUs spin while it is open. Size: small. Fit: polish (track
    C), and it matters again for M10's tickless idle.

19. **Finished plans still in `docs/`.** Where: docs/A1-PLAN.md,
    A2-PLAN.md, AS-PLAN.md, M8.5-PLAN.md; CODING-GUIDE ("finished ones
    move to docs/history/"). Code comments point at them by path
    (`abi/idl/music.idl:6`, `user/apps/splash/main.c:2`,
    `drivers/hda/hda.h:431`, ...). Size: small (a move, the links, the
    comments). Fit: M8.6 cleanup; the docs check skips docs/history, so
    their links are then checked by hand.

20. **For the code check: what is already known.** Where and what:
    - `user/services/shell/cmd/kill.c:12-40`: usage and errors go through
      `sh_say` and return 0 (the guide: `sh_tty`, 2 for usage, 1 for a
      failure); `kill`'s help (`sh_table.c:84`) and `initctl.idl`'s
      `kill` don't name the PCI drivers it reaches (`hda`, `usb-bus`).
    - Comments that say history: `kernel/include/jam/startup.h:30`
      ("(M8)"), `user/services/logd/main.c:210` ("a crash kernel"),
      `user/services/init/shell.c:64` (the shell's init channel listed
      as "kill, sync, reboot"; it also serves `mount`, `shell_ready` and
      `reboot_firmware`).
    - `user/tests/utest/music.c:14-15` includes the player's `.c` files
      (JAMJAR-REVIEW item 18).
    - Kernel waits bounded by an iteration count or not at all (ROADMAP
      follow-up: the xAPIC ICR wait, `serial_rx_start`'s drain, interrupt
      teardown, `on_cpu`, the flag locks, lockdep's graph lock).
    - Most of the shell has never had an independent review (ROADMAP).
    Size: small each. Fit: the code check.

21. **A benchmark run on the PC.** Where: docs/BENCH.md ("has not been
    run on the PC since M5.5"; the work-stealing change is "not yet
    measured on the PC"). What: BENCH.md asks for a column per milestone
    run on the PC. Size: small (the owner runs the Benchmark entry and
    photographs the box). Fit: M8.6's sign-off session.

22. **Small items left by the reviews, cheap to take on the way.**
    - `ls` and `find` show a directory's first 256 entries and say
      nothing about the rest (`user/services/shell/sh.h:245`, M8-REVIEW
      item 19).
    - "In order" plays an album in byte order, jamjar lists it ignoring
      case (`user/services/music/tracks.c:230-247` vs
      `user/apps/jamjar/library.c:165-185`, JAMJAR-REVIEW item 15).
    - `prev` just after `play` remembers a track twice
      (`user/services/music/player.c:480-503`, JAMJAR-REVIEW item 16).
    - Ports on hubs are retried only on a port status change, root ports
      on a timer (`drivers/usb-bus/hub.c:182`, ROADMAP): track A's
      backing-off retries could cover both.
    - The PC's mouse report descriptors from the boot log into
      `drivers/hid/fixtures.c` (ROADMAP).
    Size: small each. Fit: whichever track owns the file.

## Later

1. **Asynchronous bulk transfers in usb-bus, asynchronous storage calls in
   devmgr.** Where: `drivers/usb-bus/bulk.c` (`td_wait`),
   `user/services/devmgr/disk.c` (2 s waits); M8-REVIEW item 8. What: one
   bulk transfer at a time inside usb-bus's loop (up to 5 s reads, 10 s
   writes) answers no other channel meanwhile. Size: large (a redesign of
   the serve loop). Fit: M11.5, or M12's interface review.

2. **A user-space lock that sleeps.** Where: `user/apps/jamjar/cover.c:228-239`
   and `link.c` (spinlocks that busy-wait with no yield); JAMJAR-REVIEW
   item 13. What: libos has no futex-like wait, so user locks spin.
   Size: medium (a kernel wait-on-address or an event per lock). Fit:
   M12, before M13's POSIX needs one.

3. **The mixer's synchronous calls to the driver.** Where:
   `user/services/mixer/output.c:42-71,426-444`; AUDIO-REVIEW item 16,
   A2-PLAN "Left for later". What: finding the driver (2 s per service),
   `position` and the gain are calls inside the mixer's one loop, so its
   clients wait while the driver restarts. Size: medium. Fit: M12.

4. **The hda driver's one loop.** Where: `drivers/hda/irq.c:319`,
   `jack.c:216`, `ctrl.c:306-313`; AUDIO-REVIEW items 12 and 13. What: a
   codec that stops answering makes each jack poll take 1.4 s, the mixer
   sees late periods, and clear-behind can miss a ring (old samples
   replayed once); a RIRB flag cleared before its entry is taken waits
   for the next drain. Size: medium. Fit: M12 (or A3 if USB audio comes).

5. **An hda driver that dies mid-stream leaves the path open.** Where:
   `drivers/hda/stream.c:50`; AUDIO-REVIEW design question D (its
   recommendation: leave it). What: bus mastering goes off, the codec
   path stays unmuted until the restart resets the link, or for good if
   devmgr gives up. Size: medium (D3hot on an unclean exit). Fit: M10
   (power states), if ever.

6. **devmgr's protocol is hand-written; `console.write` always sends 2048
   bytes.** Where: `user/include/devmgr.h`, `abi/idl/console.idl:11`.
   What: the one protocol outside the IDL, and an IDL with only
   fixed-size arrays. Size: medium each. Fit: M12.

7. **Files over 800 lines in the kernel.** Where: `kernel/object/vmo.c`
   (1188), `kernel/sched/sched.c` (1027), `kernel/mm/aspace.c` (921),
   `kernel/test/bench.c` (1433) and five test files. Size: medium
   (internal headers). Fit: M12 (or the code check, if it has time).

8. **The address-space switch got about 20 ns dearer with PCIDs.**
   Where: docs/BENCH.md (M5.5), `kernel/arch/x86_64/pcid.c`
   (`pcid_load`'s bookkeeping). Size: small to look into. Fit: M11.5.

9. **GPT sticks are not read.** Where: `drivers/usb-storage/block.c:22`;
   decided "left out for now" (HISTORY, 2026-09-30). Size: medium. Fit:
   no milestone yet; after M9.

10. **init's loop waits up to 25 s in `mount` and 15 s in `kill`.**
    Where: `user/services/init/ctl.c:44,46`; M8-REVIEW item 20. What: no
    service is restarted meanwhile. Size: medium (asynchronous control
    calls). Fit: M12, or with a service dependency graph (ROADMAP's
    design ideas).

11. **The music player's titles come from the path.** Where:
    `user/services/music/tracks.c`; A2-PLAN "Left for later" (also
    seeking, a queue or playlist, repeat and in-order modes, resuming
    after a restart). What: jamjar already parses ID3v2 for covers; the
    player and `music status` don't read titles. Size: medium. Fit: after
    M8.6 (with the settings file in place); the ID3 parser would then
    belong in libos, outside the player's privileges as M8.6 decision 4
    asks.

12. **The horizontal wheel is parsed but not sent.** Where:
    `abi/idl/input.idl:21` (no field), ARCHITECTURE "Graphics". Size:
    small. Fit: G1, when the compositor's input protocol is designed.

13. **`mp3_sniff`'s free-format scan.** Where: `user/lib/mp3.c:121`;
    AUDIO-REVIEW item 15. What: a crafted 8 KiB of free-format headers
    costs about 33 million header parses once per file. Size: small. Fit:
    later; once `play` is its own program (track B) it costs only that
    program.

14. **Report dr_mp3's stream-cursor bug upstream.** Where: A2-PLAN "MP3"
    ("worked around, not patched ... Worth reporting upstream"),
    `user/lib/mp3.c`. Size: small, the owner's call (a public issue).
    Fit: any time.

15. **What "blank" means for `/data`.** Where: `user/services/fat/disk.c:95`;
    M8-REVIEW item 16 (a design note). What: a `/data` whose first sector
    is damaged is formatted again. Size: small. Fit: later, with a
    filesystem check if one ever comes.

16. **`/data` is not private to Jam OS.** Where: docs/HARDWARE.md (USB):
    Windows and macOS write their own folders onto the stick when it is
    plugged in there. What: nothing in Jam OS assumes otherwise
    (M8-REVIEW item 13), but `allow`'s approvals live in `/data/etc/allow`
    (decision 3), which any other computer can edit. Size: small to note,
    larger to fix (a signature or a hash per approval). Fit: worth a line
    in M8.6's design for `allow` now; a fix later.

17. **Audio timing that is estimated, not measured.** Where: AS-PLAN
    "Left for later" (the splash's sound start is a guess corrected
    once), A2-PLAN (`played` interpolated within a period; the codec's
    own delay unmeasured). Size: small each. Fit: later, if lip sync ever
    matters (G1's video).

18. **`job_find_process` is used only by its own test; `hda_pin=<nid>`
    was never built.** Where: `kernel/object/job.c` (ROADMAP), A1-PLAN
    stage 1 (needed only by a board whose firmware describes its front
    jack badly). Size: small. Fit: the code check (the first); not
    planned (the second).
