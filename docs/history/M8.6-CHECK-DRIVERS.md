# M8.6 code check: drivers

An independent read of `drivers/` at main febd124 against CODING-GUIDE.md
and ARCHITECTURE.md: usb-bus (first of all its task rewrite, fab53f2
and the commits around it, never reviewed before), hid (the report
descriptor parser above all, the one input a device writes freely),
usb-storage (the read-only one-copy path, cd77f11), hda (the query
channels, 572a381; the rest had the audio review), and their tests.
Findings first; each one's outcome is filled in as it is fixed.

Severity: **High** lets a device or a program reach what it should not,
or hangs or corrupts the driver; **Medium** is wrong behaviour a user
will meet, or one device's trouble holding up others; **Low** is a narrow
race, a wart, or a rule of the guide broken.

Nothing High was found. What held up under a careful read:

- **The task switch.** `usbbus_task_switch` saves exactly the System V
  callee-saved registers; a new stack is 16-byte aligned (the heap's
  blocks are) and laid out so `task_entry` is entered as after a call.
  Only the main loop starts and runs tasks, a task only switches back to
  the main loop, and a finished task's slot is freed after it switched
  away. The deepest path measured with `-fstack-usage` (a device task
  serving a request: `serve_chan` 240 bytes, `usb_serve_one` 2304,
  `usb_control` 160, the log's printf) stays near the header's 4 KiB of
  the 32 KiB stacks.
- **Every wait loop looks again after waking.** Each place a task waits
  (`hc_command`'s turn and completion, `ep0_take`, `addr0_take`, the bulk
  turn and `td_wait`, `control_locked`, the port resets, `wait_port_free`,
  `hc_sleep`) rechecks what another task may have changed (the device
  gone, the controller dead, the driver stopping, the lock free), and
  nothing a task keeps across a wait goes stale: a device is held
  (`dev_hold`) by every task that uses it, so its entry is never freed
  under it; its input context is only ever filled by one task at a time
  (the port task until `attached`, the device task after); `f->bulk` is
  only changed by the device's own task.
- **No lock cycles.** The command ring, a device's EP0, the default
  address and the bulk turn are each held for a bounded time, and the one
  nesting (a device's EP0, then its TT hub's EP0 for CLEAR_TT_BUFFER)
  never runs the other way. A port task holding the default address
  waits only for the hub's EP0 and the command ring, whose holders don't
  wait for the default address.
- **Detach at any step** marks the whole branch gone without waiting,
  closes its channels, and frees entries children first once no task
  holds them; a task in the middle of a step sees `gone` at its next
  check (a control transfer at once, an Address Device try between
  tries, a bulk transfer at once).
- **The xHCI rules**: one command at a time with Command Abort and a No
  Op in place of an unfetched aborted command; Address Device (BSR=0)
  tried twice for 250 ms; USB 2 root ports reset with PR, USB 3 ones left
  to train (warm reset when stuck); hub ports reset one per root port's
  tree, the slot's TT fields set for full/low speed behind high speed and
  inherited below a full-speed hub; Disable Slot before a DMA page goes
  back to the pool. The default address per root port's tree is right
  for xHCI: each root port is a link of its own, and a hub repeats
  downstream only into its own tree.
- **Untrusted device data**: configuration, hub, string and HID
  descriptors are walked with every length checked against what arrived;
  the HID report descriptor parser bounds items, nesting, pushes, sizes,
  counts and report bits and only decodes fields inside the report that
  came (`hid_rd_parse`, `hid_rd_decode`), and its fuzzing self-test runs
  in utest. usb-storage checks every MBR entry against the disk, every
  block request against its partition, and the CSW's signature and tag.
- **The read-only one-copy path** (cd77f11): the client's buffer handle
  has no `RIGHT_WRITE`, so it can neither resize nor decommit the VMO
  usb-storage maps (the kernel wants `RIGHT_WRITE` for both).
- **hda's query channels**: `open_output` and `query` are refused on
  them before the dispatch; they close with the driver; a stale key is
  ignored.

### Design questions

- **A. Bulk transfers per device (item 1).** Concurrency per device is
  the natural next step after the tasks; a fully asynchronous protocol
  (several requests in flight per channel) is still the "Later" item of
  M8.6-CANDIDATES.md and not needed for sticks.
- **B. TD hand-off (item 8).** Writing a TD's first cycle bit last is the
  robust way; it changes every transfer's TRB writes and only the PC can
  show it matters. Left for a change that can be tried on the PC.
- **C. A kernel right to write a VMO without resizing it (item 9).** With
  it usb-storage's writable channels map the buffer as the read-only ones
  do. The kernel's call.
