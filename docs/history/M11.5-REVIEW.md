# M11.5 review: the performance pass (concurrency and ABI)

An independent read of milestone M11.5 at local main bb249cc (every track
merged, the join done), by an agent that wrote none of it, against
CODING-GUIDE.md, ARCHITECTURE.md (IPC, Scheduler, the system call ABI),
`abi/syscalls.def` and docs/M11.5-PLAN.md. The owner's scope: the channel
paths (`kernel/object/channel.c`, `channel_send.c`, `channel_internal.h`,
`kernel/abi/channel_sys.c`, `sysc_channel.c`), the scheduler's direct
hand-off and `preempt_check`, the FPU system-call rule and its `in_syscall`
flag, the lock checker's fast path, the cheaper deadlines and the PCID
slot hint, genidl's serve loop and `_within` stubs (M11.6's slot stubs
only where they reach the call path), the soak's message-byte growth, and
which bench line the 600 ns target is read on. Correctness first, speed
second.

Severity: **High** corrupts memory, leaks another thread's or process's
state, loses or misdelivers a message, or deadlocks; **Medium** is wrong
behaviour the owner will meet, or a rule the design relies on that does
not hold; **Low** is a narrow case, a performance wart, a gap in a check
or a rule of the guide broken.

**Nothing High or Medium was found.** What held up under a careful read
(each argued in full below the table where it is not obvious):

- **One copy in and out.** Bytes are copied from user memory into a
  message that is not yet visible to anyone (`msg_make`, no lock held),
  once; the txid is stamped over the copy afterwards, so a sender that
  changes its buffer mid-copy only changes its own message. Out, the
  message is off every queue (or handed, so off every list) before
  `chan_msg_deliver` copies, so a fault or a peer closing mid-copy can
  only lose that one message, and then its handles are released
  (`chan_msg_drop`). A close of either end is decided under the pair
  lock, before or after the send as a whole.
- **Per-thread slots.** Slots are conserved: a slot is either a thread's
  `msg_slot`, on offer in exactly one listed `chan_waiter.slot` (taken out
  of `msg_slot` first), or the body of a message in flight to one waiting
  thread, which delivers it in the same system call and keeps it as its
  own (`chan_msg_free` -> `chan_slot_keep`; a second slot is freed). Only
  the current thread touches its own `msg_slot` (the swap in
  `swap_slots_locked` writes the writer's own, and reads the waiter's
  offer under the waiter's endpoint lock while it is still listed), and
  no channel write runs in interrupt context (the only kernel writer is
  `userboot.c`), so an interrupt can't race it. A slot message is never
  queued: one that finds nobody becomes a charged copy first
  (`chan_msg_unslot`), so `channel_close` never drops a slot. A thread
  never exits inside a channel wait (cancellation returns through the
  normal path, which gives the offer back), so `thread_reap`'s
  `kfree(t->msg_slot)` frees nothing referenced.
- **The no-relock protocol.** `hand_to_locked` unlists the waiter, wakes
  it, and only then publishes the message with a release store; after
  that store it touches neither the `chan_waiter` (on the waiter's stack)
  nor the thread. A waiter that finds the message (acquire) returns
  without the endpoint lock; one woken before the store (by the wake
  itself, a deadline, a cancel or a close) doesn't find it and takes the
  lock, which the writer holds until the store is done. Under the lock
  "listed" and "not handed" are the same thing, so every error path
  (`ERR_CANCELED`, `ERR_PEER_CLOSED`, `ERR_TIMED_OUT`) either still owns
  its listing or has the message, and a handed message wins over every
  error. The other wakers can't outlive the waiter's return either: the
  deadline timer's wake is serialised by the sleeper-queue lock that
  `block_prepared` takes after the switch, and `wake_callers_locked` (a
  close) runs under the very endpoint lock the hand-over needs.
- **`channel_reply_wait`**: every error path matches `abi/syscalls.def`.
  The request's handle slots are reserved before the reply goes out; a
  reply failure gives them back (`fill_reserved` with 0); the mark is
  written only after a reply that went out (not for `ERR_PEER_CLOSED`,
  which by the ABI text did not go out), and a mark fault ends the call
  after the reply; `reply_status` is written as the call returns, with
  the sizes, whatever the wait did; `sched_handoff_done` runs on every
  path that can have recorded a hand-off. The port form needs `RIGHT_READ`
  as `port_wait` does; the same-handle form needs both rights. Replies are
  still found by (channel end, txid) in `find_caller_locked`, which is all
  M11.6's successor needs.
- **`hand_over_locked`'s three cases** (a caller waiting for the txid, the
  longest-waiting reader that fits when nothing is queued, the queue) keep
  `chan_waiter`'s rule that a listed reader's endpoint has an empty queue:
  a reader lists itself only on an empty queue, and a message queued
  because it fit no reader unlists and wakes every reader.
- **The direct hand-off.** `rq->handoff` is read and written only by its
  own CPU, always with interrupts off: in `hand_off` (which checks
  `c->index == cpu && c->current == me` after `irq_save`, so a waker that
  migrated since its placement queues instead), in `schedule()` and in
  `sched_handoff_done`. No other CPU's code names it (try_steal, placement
  and the tick read only `nr_ready`, `busy` and `cur_prio`). Every
  `schedule()` on the CPU takes it, so `handoff_from` is always the
  current thread while one is recorded, and a waker that is preempted
  (prev still `T_RUNNING`), has no slice left, or finds a higher-priority
  thread queued queues its wakee instead. The wakee is `T_READY` on no
  queue meanwhile: every other waker sees `T_READY` and does nothing, as
  in `place_on`'s own window, and nothing else looks for a `T_READY`
  thread on a queue. Both users (`send_request`, `rw_reply`) end with
  `sched_handoff_done`. Slice inheritance and the priority rule are as
  the plan says.
- **`preempt_check`'s fast path.** A need_resched set by another CPU
  always comes with an IPI (or is seen by a polling idle CPU), which is
  taken on interrupt exit; one set by this CPU is set under a lock, i.e.
  with preemption off, and the unlock's own `preempt_check` (after
  `irq_restore`) sees it, on this CPU, since the GS-relative load can't be
  split by a migration. With interrupts off or a nested `preempt_disable`
  nothing changes from before (the reschedule waits for the next safe
  point, as it did).
- **The FPU rule.** `in_syscall` is set and cleared with interrupts off
  (`syscall_entry_c`), so a switch never sees it half-way; a ring-3
  interrupt or exception switches out with it clear and saves in full; a
  thread that leaves for good inside a call is `T_DEAD` and saves nothing;
  `arch_enter_user` clears it for a new thread; there are no signals (no
  code redirects a user RIP) and kexec keeps no thread. `fpu_save_called`
  reads the control words from this CPU's registers, which always hold
  the outgoing thread's state (they are only ever loaded by `fpu_load`,
  which records the owner), turns the area into an almost-initial state
  (XSTATE_BV 0, or x87 only with an empty stack; XRSTOR loads MXCSR
  whatever XSTATE_BV says; XCOMP_BV and the reserved header stay 0), and
  sets `fpu_cpu` to none so the next switch in restores it: the registers
  that still hold the old values are never trusted again. PKRU and CET
  can't be dropped: the rule is off unless XCR0 is x87/SSE/AVX only.
- **The lock checker's fast path.** Push raises the depth and then fills
  the slot; pop empties the slot and then lowers the depth; every slot at
  or above the depth is empty. An interrupt handler between any two
  steps pushes above, skips an empty slot in its edge scan, and pops back
  to exactly what it found. A release that isn't the top goes the slow
  way with interrupts off. `HOLDER_CHECKED` makes a release checked
  exactly when its acquisition was, so `lockdep_set` can flip with locks
  held anywhere (an unchecked lock held while checked ones are taken just
  adds no edges). The self-deadlock check moved from the list to the
  lock's holder field; the window where the holder field is not yet (or
  no longer) ours is one where an interrupt handler taking the same lock
  would already break the interrupt rule, which `irq_rule` reports before
  it spins.
- **Deadlines.** `deadline_of` saturates an overflowing timeout to
  `DEADLINE_NEVER`, and `uptime_to_tsc` saturates a far one, so no
  timeout wraps into the past. A far head skips the timer write and the
  tick re-arms for it at every tick (`on_timer` -> `sched_timer_expire`
  -> `sleepq_arm` -> `timer_program`); the dependence on the tick is
  finding 2.
- **PCID hint.** `find_slot` checks the hinted slot's id before using it,
  so a stale hint (an epoch reset, a slot reused for another id) only
  costs the old search; ids are never 0 there (`!id` takes the PCID 0
  path first).
- **genidl.** `idl_serve_next` sends the waiting reply in the
  `channel_reply_wait` that takes the next request, closes the reply's
  handles exactly when it did not go out (`rs != OK`), retries the wait
  without the reply when the reply failed and nothing was read, and
  drains a request that doesn't fit; `_within` passes the timeout to the
  kernel unchanged (the kernel saturates it). `idl_take_after` and
  `idl_reply_flush` use a wait of 0, which `read_wait_locked` turns into
  `ERR_TIMED_OUT` before it would list itself.

### Design questions for the owner

- **A (finding 3): txids.** Options: (a) leave it (the wrap needs a call
  outstanding for ~2^32 others, on the same endpoint); (b) make the txid
  space per endpoint pair (a counter in `struct chan_pair`), which keeps
  replies addressed by (channel end, txid) and moves the wrap to 2^32
  calls on one channel; (c) skip, on allocation, a txid that a caller on
  the same end still waits for (a list walk per call). Recommendation:
  (b) at M12, which reviews the call ABI anyway; it changes nothing a
  client sees, and the "two endpoints calling each other" reason for a
  global counter is already covered by `find_caller_locked` only looking
  at callers on the reply's destination end.
- **B (finding 4): guards with the checker off.** Either count spinlocks
  per CPU without the checker (one GS-relative increment and decrement
  per lock, about what `preempt_count` costs) so `can_trim` and
  `check_callable` see them in every boot, or accept that a `nolockdep`
  boot (the bench's checker-off column only) has weaker guards.
  Recommendation: accept it and say so next to `nolockdep` in
  TESTING.md's boot words; the everyday boot keeps the checker (Q1 a).
- **C (finding 7): the soak's message-byte limit.** The limit's purpose
  is to catch messages piling up; one pending NS_SET is by design, and
  its size grows by 1,056 bytes per service the shell is given (G1 adds
  the compositor's). Options: (a) have the soak script run a command
  that resolves a path (any `ls /`) before `reboot -f`, so the shell takes
  its NS_SET and the figure measures real queues (~3.9 KB today);
  (b) raise the limit to 64 KiB; (c) both. Recommendation: (a): it keeps
  the check sharp, and an unread NS_SET is already bounded by
  `ns_update`'s take-back.
- **D (finding 8): the 600 ns target's line.** Three lines now measure
  "a process-to-process call": bench-echo (`user: process->process
  channel_call, same CPU (P)`: read, write, read, wait; 5 system calls; a
  server shape no generated server has any more), the reply-and-wait
  server (`user: call to a reply-and-wait server`: 2 system calls, no
  deadline), and the generated one (`user: generated client and server
  (null.ping)`: the same 2 system calls plus a time limit, so two clock
  reads and a sleeper entry). Recommendation: **read the target on the
  reply-and-wait line, checker on**: it is the IPC path itself (what the
  roadmap's "one reply-and-wait call, a direct hand-off, one copy" names,
  and what other kernels' call numbers measure: no deadline), and every
  server written since M11.5 uses it. Print the generated line next to it
  as "what programs pay" (the reply-and-wait line plus the time limit's
  cost), and keep bench-echo as the history line (it is the only one
  comparable with M5 to M8.6). Not decided here.
